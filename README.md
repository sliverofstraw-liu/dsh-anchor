# dsh-anchor

在长讲解里遇到疑问，就地在那一处提问；答案进入对话流，原处留下可以点回去的标记。

给 DeepSeek Harness（DSH）用的插件。

## 它解决什么

AI 讲一章内容，一次输出几千字。你读到中途冒出一个疑问，问完之后想回到刚才那句，得往上翻半天。

这个插件让你：

- **就地提问**：拖选一段文字 → 点「提问」，不用复制粘贴原文
- **指代明确**：选中的文字、所在位置和上下文会随这一轮提问一起告诉模型
- **一键回去**：答案底部有图钉标签，点它回到原文；引用条上的 ↓ 回到对应回答
- **看得见痕迹**：问过的位置留淡黄底色，方便回看

## 安装

需要 DSH 支持插件（profile 里有 `dsh.profile.bundles` 字段的版本）。

桌面版：

```bash
dsh plugin --profile desktop add github:sliverofstraw-liu/dsh-anchor
```

用 `dsh web` 启动的网页版，把 `desktop` 换成 `web`：

```bash
dsh plugin --profile web add github:sliverofstraw-liu/dsh-anchor
```

装完**重启应用**（宿主半边只在启动时加载），然后刷新页面。

> profile 写错是“装了但没反应”最常见的原因：桌面应用只认 `desktop`，它自己管理这个 profile。

卸载：

```bash
dsh plugin --profile desktop remove dsh-anchor
```

## 用法

| 操作 | 结果 |
|---|---|
| 拖选正文里的一段文字 | 浮出「提问 / 复制」 |
| 点「提问」 | 输入框工具行出现引用条，正文出现淡黄底色 |
| 正常发送你的问题 | 模型收到位置 + 原文 + 上下文 |
| 回答底部出现 `📍「…」` | 点它回到原文 |
| 点引用条上的 `↓` | 去到这次提问对应的回答 |
| 点引用条上的 `✕` | 结束这处追问（痕迹转浅） |
| 点工具行的眼睛图标 | 隐藏所有荧光，方便截屏（不删数据） |
| 点已问过的荧光 | 弹出该处的问题，可「看答案」或再问一次 |

同一处不能重复框选；想再问，点那处荧光即可。若把同一段文字重新框选一次，会用它这次的位置刷新旧锚（定位偏了的时候可以这样纠正）。

## 它会做什么（请先读这一节）

装在别人机器上时，这个插件会：

1. 在**本机**注册三个 HTTP 路由（只接受 loopback 请求），用于接收、清除当前锚点，以及给调试面板读取状态：
   - `POST /dsh-anchor/state`
   - `POST /dsh-anchor/clear`
   - `GET /dsh-anchor/debug`（只读，供调试面板显示「这一轮注入了什么」）
2. **每轮对话往系统提示里追加一小段上下文**，内容是当前锚点的位置、原文和所在段落。没有锚点时什么都不加。
3. 在浏览器 `localStorage` 里保存锚点，键前缀 `dsh-anchor:v2:`，用于刷新后恢复。

不含任何网络上报、遥测或外部请求。

## 出问题时怎么自查

按 **Ctrl + Alt + D**（mac 上是 ⌘ + Alt + D）打开隐藏的调试面板，再按一次关闭。

面板里有两块：

- **本地状态**：有几条锚、几条痕迹、几条提问记录、多少个用户消息被打了标记，以及每条锚当前能否在正文里定位到（✓ / ✗）
- **注入的提示词**：宿主这一轮**实际**塞进系统提示的原文，和模型看到的一字不差

常见读数：

| 现象 | 含义 |
|---|---|
| `✗` 出现在某条锚上 | 那条锚定位失败，荧光和跳转都会不准 |
| 「注入的提示词」一直是空的 | 锚点没上报到宿主，检查宿主是否正常加载 |
| 提问记录 0 条 | 发送没被识别，图钉标签不会出现 |
| 已贴标记 0 个 | 用户消息上没打上标记，`↓` 会退化 |

## 已知限制

- **位置靠 DOM 推断**：锚点绑定消息 id，但回答还在生成、或消息被重渲染时可能退化到较弱的定位方式，偶尔会落偏。清空后重来即可。
- **锚点只注入第一枚**：同时存在多枚引用条时，只有第一枚会传给模型。
- **只在本浏览器有效**：`localStorage` 按浏览器存储，换机器或清缓存会丢。

## 兼容性

- 依赖 DSH 的客户端插槽：`shell.overlay`、`conversation.input.left`、`conversation.chat.assistant-actions`。
- 依赖宿主服务：`webServer`、`systemPrompt`。
- 没有构建步骤：`client/client.js` 是手写的模块包装，`lib/index.js` 是纯 ESM。

## 开发

```
dsh-anchor/
  lib/index.js        宿主半边：存锚点、注入提示词、注册路由
  client/client.js    客户端半边：选区、引用条、荧光、标签、跳转
  cordis.patch.yml    把插件插进 profile 的补丁
  test/smoke.mjs      客户端 bundle 的加载契约冒烟测试
```

改完客户端跑一下：

```bash
node test/smoke.mjs
```
